# Team Workspace

**Собственное рабочее пространство для команды — задачи, мероприятия, сметы и знания в одном приложении.**

Рабочее пространство для команды: задачи и канбан, мероприятия и сметы, расписание и занятия, документы, база знаний, аналитика и профили сотрудников.

Это отдельная универсальная версия приложения. Она не содержит базу, сотрудников, мероприятия, вложения, домен или секреты исходной организации. Название, адрес сайта и часовой пояс задаются при установке. Каждый экземпляр независим; общей многопользовательской SaaS-платформы здесь нет.

## Быстрый запуск

Проверенная версия — Python 3.12; установщик требует Python 3.12 или новее. Скачайте ZIP через **Code → Download ZIP** или клонируйте репозиторий:

```bash
git clone https://github.com/ognewmax-eng/team-workspace.git
cd team-workspace
```

Затем выполните внутри каталога проекта:

```bash
python install.py
```

Установщик спросит название организации, адрес и часовой пояс, создаст закрытый `.env` с уникальным ключом, установит зависимости в `.venv`, применит миграции и предложит создать первого директора. Его пароль не записывается в конфигурацию. Повторный запуск не сбрасывает настройки и пользователей.

Локальный просмотр:

```bash
.venv/bin/python manage.py runserver 127.0.0.1:8080
```

Windows: `.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8080`.

Откройте http://localhost:8080. `runserver` предназначен для локального просмотра. Для постоянной работы используйте один из способов ниже.

## Docker на сервере

Установите Docker Engine с Compose. DNS вашего домена должен указывать на сервер; порты 80 и 443 должны быть доступны.

```bash
python3 install.py --mode docker
```

Введите `https://ваш-домен`. После создания директора включите HTTPS-прокси:

```bash
docker compose --profile server up -d proxy
```

Caddy автоматически получает сертификат. Django доступен напрямую только на `127.0.0.1:8080`. База, локальные вложения и статика хранятся в постоянном томе `workspace-data`; сертификаты — в отдельных томах. Не используйте `docker compose down -v` на рабочем экземпляре: это удалит данные.

Для Docker без внешнего домена используйте `http://localhost:8080` и не запускайте профиль `server`.

## Хостинг без Docker

Нужны поддержка Python 3.12+, WSGI/Passenger, SSH, отдельное место для закрытых данных и возможность перезапускать приложение. Обычный хостинг только для PHP или статических страниц не подойдёт. Пошаговая настройка: [docs/HOSTING.md](docs/HOSTING.md).

## После установки

Войдите директором. Через админку создайте отделы, сотрудников и назначьте роли. Добавьте собственные задачи и мероприятия. Excel-шаблон скачивается из раздела «Мероприятия → Импорт». Установка не загружает демонстрационные мероприятия или данные другой организации.

Файлы по умолчанию локальные и закрытые: скачивание требует входа и прав на связанный документ, задачу, статью или мероприятие. Каталог `data/media` нельзя раздавать напрямую через веб-сервер. Synology, SMTP, Telegram и Google необязательны: [docs/CONFIGURATION.md](docs/CONFIGURATION.md).

## Резервное копирование

```bash
.venv/bin/python manage.py backup_instance --directory /закрытый/каталог/копий --include-media
```

В Docker:

```bash
docker compose exec web python manage.py backup_instance --directory /app/data/backups --include-media
docker compose cp web:/app/data/backups ./backups
```

Снимок SQLite согласован на момент резервирования. Для полной копии приостановите загрузку и удаление вложений. Конфигурация `.env` и ключ `SECRET_KEY` в архив не входят: сохраните их отдельно в закрытом месте. Для Synology нужна собственная копия удалённых файлов.

Восстановление: остановите приложение и обработчик рассылок; сохраните текущие данные; извлеките проверенный архив в отдельный каталог, проверьте SQLite и замените базу и `media` согласованной копией. Верните прежний секретный ключ, выполните миграции только подходящей версии и запустите приложение. Не накатывайте старую базу поверх работающего сайта.

## Обновление

Перед обновлением остановите внесение изменений и сделайте копии базы, вложений и конфигурации. Установите новую версию исходников без замены `.env` и `data`. Python: установите зависимости, выполните `migrate`, `check`, `collectstatic` и перезапустите WSGI. Docker: `docker compose up --build -d web mailings`, затем проверьте `docker compose logs web`. Миграции запускаются при старте `web`.

## GitHub

В новый репозиторий переносится содержимое этого каталога. `.env`, `.venv`, `data`, базы, загрузки и резервные копии исключены из git и Docker-контекста. Проверка перед коммитом: `python scripts/check_distribution.py`. Мастер создаёт только локальные настройки; опубликованный репозиторий их не получает.

Включён GitHub Actions: установка зависимостей, миграции, системная проверка и тесты чистого экземпляра. Перед публичным выпуском определите лицензию с учётом прав на исходный проект; этот пакет сам не меняет его лицензию. См. [LICENSE_NOTICE.md](LICENSE_NOTICE.md).

## Границы первой версии

Основной профиль — небольшая команда с SQLite и двумя процессами приложения. PostgreSQL, S3, Kubernetes и установка на любой произвольный хостинг не заявлены. Статика использует существующие CDN-зависимости интерфейса, поэтому клиенту нужен доступ к ним. Смена названия обновляет интерфейс, но не автоматически содержимое ранее написанных статей/писем.

Django 5.2 LTS выбран для независимой версии; исходный рабочий сайт не обновляется этим пакетом. Перед использованием реальных данных проведите пробную установку, загрузку/скачивание вложения и восстановление резервной копии на выбранном сервере.
