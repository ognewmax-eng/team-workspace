# Python-хостинг и Passenger

1. Уточните у провайдера поддержку Python 3.12+, WSGI/Passenger, SSH и выбранного домена. Старый Python 3.8 не подходит для этой универсальной версии.
2. Создайте отдельный экземпляр и пустой каталог. Исходники разместите вне публичной папки документов либо запретите прямую HTTP-раздачу всего каталога проекта. Не размещайте `.env`, SQLite и `media` в публичном корне.
3. Настройте DNS и HTTPS в панели хостинга.
4. Выполните `python3 install.py` в каталоге проекта. Укажите `https://ваш-домен`.
5. В панели Passenger задайте Python: `/полный/путь/к/проекту/.venv/bin/python`, application root — каталог проекта, startup file — `passenger_wsgi.py`. `sys.executable`/venv старого сайта не копируйте.
6. Если нужен отдельный закрытый файл конфигурации, задайте `WORKSPACE_CONFIG=/закрытый/путь/workspace.env` перед установкой и в окружении Passenger. Аналогично `DATA_DIR=/закрытый/путь/workspace-data`. Эти переменные должны совпадать в SSH и веб-приложении.
7. `TRUST_PROXY=True` включайте только когда провайдер гарантирует замену `X-Forwarded-Proto` своим прокси. Если HTTPS доходит непосредственно до WSGI, это не требуется. Не позволяйте клиенту подставлять доверенные заголовки.
8. Статику обслуживает WhiteNoise после `collectstatic`. Не добавляйте публичный alias для `/private-files/` или каталога `media`.
9. Перезапустите приложение средствами панели; при Passenger с поддержкой restart-файла: `mkdir -p tmp` и `touch tmp/restart.txt`.
10. Проверьте вход директором, загрузку и скачивание файла, импорт Excel, доступ другого пользователя, резервное копирование.

Для рассылок добавьте cron раз в минуту с абсолютным путём к Python, `cd` в каталог проекта и `manage.py process_mailings`. SMTP должен быть настроен; без него письма не отправляются. Для резервирования добавьте ежедневный cron `manage.py backup_instance --directory /закрытый/путь/копий --include-media`; час определяется часовым поясом сервера. Не вставляйте пароли в команды cron.

Открытая регистрация использует существующий процесс подтверждения сотрудников. Директор управляет доступом и ролями через админку. Не назначайте обычным сотрудникам `is_superuser`.
